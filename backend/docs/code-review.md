# 后端代码评审清单

评审按风险和证据优先，不以格式性评价代替行为检查。

## 正确性

- 需求、错误码、状态转换、金额和并发版本是否由服务端重新验证。
- 幂等键是否绑定 actor、store、route 和请求摘要；旧版本或迟到结果是否明确拒绝。
- 数据库事务是否足够短，并避免远程 I/O、图片处理或推理。

## 边界

- 依赖是否保持 `transport → application → domain`，基础设施是否只实现 application port。
- Domain 是否仍为纯 Python，Transport DTO、ORM 和配置是否停留在边界。
- OpenAPI、共享识别契约、迁移和前端消费者是否只有一个事实源。

## 安全与运维

- 错误、日志和生成物是否排除凭据、数据库 URL、私有图片地址与原始模型输出。
- 外部 I/O 是否有超时、取消、资源释放、重试上限和安全错误映射。
- 就绪检查、迁移、回滚、监控和残余风险是否有可执行说明。

## 验证证据

- 新生产行为是否有旧实现会失败的自动化测试。
- `make verify` 是否零 warning 通过；数据库行为是否用真实 PostgreSQL 验证。
- 无法自动化的微信、对象存储、模型硬件或真机验证是否明确列为未执行。
