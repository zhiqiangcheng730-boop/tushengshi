## 1. 验收层次

| 层次 | 证明什么 | 不可替代的证据 |

| 设计原型 | 页面、流程、状态和文案能被理解 | HTML 实际操作与走查记录 |

| 门店试点 | 店员完整任务是否省时、能独立完成 | 真实操作、整桌时间、最终数量与签费 |

任何一层成功均不能代替下一层。HTML 示意数据不进入模型准确率分母。

## 2. 数据与真值

第一批至少 30 张实物照片冒烟；探索集目标 100～200 张；正式独立测试建议至少 500 张，目标覆盖至少 3 门店、3 类手机。数量均为规划建议，正式测试前冻结；不足时明确结论适用范围。

采集顺序：实物编号 → 两次独立人工清点，分歧重数 → 在不增减实物的条件下拍摄 → 每个可见端面点标 → 第三方或另一轮复核。照片不可见端面与实物根数不一致时标注为遮挡／不合规范，不强造不可见点位。

保留两类真值：physical_count 与 visible_endpoint_count，以及是否符合支持规范。正式可清点范围要求二者一致；不可见照片进入拒识／拍摄测试。范围判定由标注流程预先完成，不能看模型结果后挑选。

每条 manifest 包含 sample_id、bundle_id、store_id、phone_id、数量档、光线、拍摄角度、原图哈希、拍摄规范判定、实物真值、可见点位、标注与复核人、split。同一实物束的不同照片不跨训练／调参／正式测试集合。

保留挑战集：断签、杂物、反光、无目标、出框、严重模糊、完全遮挡、密集超范围。挑战集单独报拒识与错误；若符合预先声明支持范围，就必须计入正式分母。

## 3. 98% 指标定义

已确认精准目标为 98%，以下 A 为推荐口径，尚未得到用户最终确认。正式测试开始前由产品负责人冻结 D01；探索阶段同时输出 A、B，不能自行把其中之一标记为已达成用户要求。

- A：首次自动整图完全正确率 = 首次自动根数等于实物真值的合规范图片数 ÷ 全部合规范测试图片数。
- B：每张数量相对误差 = abs(自动数－真值) ÷ 真值；另报均值、P95、最大值和“误差≤2%”比例，不能用均值掩盖个别错单。
- 首次失败、拒识、超时、格式不合法均进入 A 分母但不进入成功分子；重拍、调提示重跑和人工修正不回填首次成绩。
- 预先声明不符合规范的样本单独报告；不能为过线临时排除。
- 定位另测一对一匹配后的漏检、误检、重复；总数碰巧抵消不能算逐根定位正确。

500 张中 490 张全对对应观测值 98%，并不证明所有门店的总体准确率都至少 98%。报告必须有样本数、分层结果与统计不确定性说明；若需要“置信下界≥98%”，需另外设计样本量和判定规则，不能沿用 490／500 自动通过。

整桌指标：自动未修正全桌正确率、人工确认后最终数量正确率、最终签费错误数、未完成率、人工兜底率、总操作时间。单张指标不自动推导为整桌指标。

## 6. UI 与易用性

招募目标为 3～5 位不同熟练度店员，属于探索性可用性测试，不是准确率统计样本。无店员时先内部走查，报告明确区分。

| ID | 独立任务 | 观察与通过条件 |
| --- | --- | --- |
| UX01 | 首次打开完成一把 | 无主持人操作帮助完成，知道当前是否确认、是否保存 |
| UX02 | 找到并修正漏点／多点 | 能区分浏览和编辑，缩放不误改，能撤销；记录修正时间与误触 |
| UX03 | 两把累计、第二把重拍并取消 | 能说明当前合计为何变化；没有将同把重复累计 |
| UX04 | 网络失败转人工、切微信再恢复 | 原图和输入仍在，知道未同步状态，最终只生成一份有效记录 |
| UX05 | 改错组别、完成、顾客核对、更正 | 无需重拍改组；能解释单价与签费；旧单历史可追踪 |

现场总耗时从拿起待数实物开始，到最终确认签费结束，包含整理、重拍、等待、纠错和转人工。人工基线使用相近数量与条件，交叉任务顺序，避免一律先手数造成记忆优势。

建议试点体验目标：独立任务完成率≥90%，整桌中位耗时较人工减少≥30%，P90 不比人工基线更慢；这些属于 D06 待冻结建议。人工确认后数量和签费在试点验收样本中必须无错误；出现错误逐单分析与修复，不用98%替代最终确认正确性要求。

I01 真机矩阵：至少覆盖 iOS／Android、较小屏和大字体、不同相机方向与相册来源。对已知标记的点击逆映射误差≤3 CSS px 为工程初始目标；200／400 点仅用于编辑器压力测试。检查视口、底部安全区、弹层、键盘、触控热区与颜色之外的状态提示。

## 7. 性能、安全与恢复

| ID | 条件 | 初始目标／断言 |
| --- | --- | --- |
| P01 | 固定硬件，单请求及5设备同时提交，连续30分钟 | 业务读写P95≤500ms；识别端到端P95≤15s为待冻结目标；分别记录上传、排队、推理，超限不得隐去 |
| P02 | 排队上限、worker未就绪、内存不足 | 有界排队，明确BUSY／不可用；查询与人工流程可用，无无限请求堆积 |
| P03 | 连续编辑与400点UI压力 | 目标设备拖动／缩放可用，无明显卡死；常规交互响应≤100ms为工程目标 |
| S01 | 跨店枚举、伪造store_id、停用成员、越权改价 | 全部拒绝；不能仅由前端隐藏按钮保护 |
| S02 | 超大／伪格式图片、私有图片URL、过期凭证 | 服务端校验，无法绕过门店权限，凭证过期失效 |
| S03 | 日志与配置 | 无AppSecret、token、原图内容或长期私有地址泄露 |
| O01 | worker退出、数据库备份恢复、对象存储失败 | 任务可恢复且无重复应用；恢复后订单／图片关联可核对；RPO≤24h、RTO≤4h待实演确认 |

不预设 GPU 型号即可达到15秒。先在 G3 固定硬件和支持范围再执行正式性能验收；未达到应记录失败和预算选择。

## 8. 端到端、回归与上线门槛

E01：真实体验版完成“加入门店→配置→两把识别→点位修正→重拍取消→人工→完成→历史→更正”，并注入一次断网和一次迟到结果。校验客户端、数据库冻结快照和整数分金额一致。

每次改动只重测受影响指标和必要回归；模型／提示／预处理／候选生成更新必须重新跑固定算法测试集，不能只看新增成功样例。

阻断问题：错数／错费无法发现或恢复、跨店越权、重复累计、数据丢失、完成快照被改写、核心路径不可完成。正式上线前必须为0。一般视觉问题可有明确责任人和修复计划，不无限追求装饰完善。

G4 必须同时满足：D01／D02／D04／D06 已冻结；指定 VLX 正式集通过；业务、安全、关键异常和真机通过；备份恢复有实录。G5 必须有真实店员试点与整桌基线对比。用户仍需在实际发布前作出上线决定，本设计不等同于发布授权。

## 9. 测试交付格式

每次运行保存：test_run_id、版本、环境／硬件、manifest哈希、执行命令、起止时间、样本数、完整结果、失败列表、限制与判断。试点额外保存匿名店员熟练度、整桌任务过程和最终实物核对。

评测原图、标注和业务图片按授权与保留规则隔离存放；训练集的人工修正必须复核后才能使用。
