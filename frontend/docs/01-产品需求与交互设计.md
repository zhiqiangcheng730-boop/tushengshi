# 数得快：产品需求与交互设计

版本 v0.2｜2026-10-16｜待评审设计稿｜[入口](../README.md)｜[HTML](../prototype/index.html)

## 1. 产品任务与用户

店员在顾客等待时，将一桌签束分组清点，核实数量，得到签费小计并留档。产品首先减少整桌操作负担，其次才增加管理功能。

| 用户 | 权限 | 常用动作 |
| --- | --- | --- |
| 店员 STAFF | 查看本店记录，编辑本人经办的未完成单，接收交接 | 拍照、修正、人工录入、确认和完成 |
| 店主 OWNER | 店员权限，加价格、邀请／停用成员、处理记录更正 | 一次性设置与异常处理 |

首版一个账号只进入一个当前门店；数据结构保留 membership，不做复杂组织树。无需索取手机号才能数签。正式身份采用微信登录，原型使用示例门店与角色。

v0.3商业化补充：面向多家独立门店收费已确认，店主服务页、运营后台和数据请求纳入商业阶段，见[08～11入口](../README.md)。这些不代表下述试点原型已实现；软件服务费与清点签费始终分开。

## 2. 核心旅程

1. 首次：店主建店并设置价格，店员凭邀请加入。已有成员直接进入工作台。
2. 打开“开始数签”，自动创建临时清点单；桌号选填，之后可补。
3. 按价格组整理签束，保持圆形端面完整清晰；待数与已数签束放在不同位置。
4. 拍照或选图，显示上传／排队／识别的真实阶段；允许取消、返回或转人工。
5. 在结果页浏览，必要时补点／删点／撤销，确认本把。
6. 查看整桌已确认根数及签费小计；新增下一把，或重拍、改组、删除某把。
7. 所有批次处理完成后，展示按组明细，再“完成清点”。
8. 历史可查原图、来源、自动与最终数量、价格快照。已完成单可由授权人发起更正。

建议默认组沿用本单上一次选择；单价始终可见。只有一个组时不用多一次选择。桌号和门店配置不阻塞常规拍摄。

## 3. 需求清单与验收

| 编号 | 需求 | 完成条件 |
| --- | --- | --- |
| FR01 | 身份与门店 | 邀请加入后进入门店；失效、离店、越权有明确结果；AppSecret 仅在服务端 |
| FR02 | 价格配置 | 名称和单价可改；每单开单快照；改价只影响后续新单；无价格可仅记数量 |
| FR03 | 开单与归属 | 自动单号、选填桌号、经办人；同桌已有未完成单时提示进入，允许明确新建 |
| FR04 | 拍摄与选图 | 有正确示例、清晰／完整提示；拒绝权限可转选图或人工；两个入口归一到同一图像规则 |
| FR05 | 异步识别 | 结果绑定图片、批次版本和尝试；等待、失败、超时、取消可辨；恢复后能查当前结果 |
| FR06 | 逐根修正 | 浏览与编辑分开；补／删／撤销；缩放拖动不误改；数量与有效点位一致 |
| FR07 | 人工兜底 | 正整数数量和原因；来源明确；自动点位、人工录入分别保存 |
| FR08 | 多把累计 | 只有当前有效确认版本入合计；新增与重拍动作明显区分 |
| FR09 | 重拍与恢复 | 重拍暂移出本把旧数量；取消可恢复旧确认版本；确认新版后仅用新版累计 |
| FR10 | 完成与金额 | 有未处理批次或无有效批次不能完成；服务端计算整数分金额并冻结快照 |
| FR11 | 历史与更正 | 能查数量、来源、图片和价格；更正保留原单，完成新单后原单作废 |
| FR12 | 草稿与弱网 | 被中断后能恢复；未同步明确展示；离线只存本地草稿，联网确认后才形成云端完成记录 |
| FR13 | 经办与交接 | 同单仅当前经办人可写；冲突不覆盖；交接保留动作记录 |
| FR14 | 顾客核对 | 可在本机展示清晰的组别×数量×单价及签费小计，不泄露店员身份凭据 |
| FR15 | 数据使用 | 展示保留期限，训练使用独立选择；撤回训练选择不影响正常清点 |

## 5. 数量、价格与批次规则

### 5.1 数量语义

- 自动结果必须是一组合法点位或实例框。自动数量等于通过适配校验后的实例数，原始输出另存。
- 点位修改后的最终数量等于有效点位数；补点／删点有撤销记录。
- 人工录入数量范围建议 1～9999；0 个目标显示“未发现可清点签头”，不确认空批次。
- 人工录入不要求伪造点位。展示“人工清点 N 根”，同时保留识别曾输出的内容。
- 正整数校验、异常数量提示与图像支持上限分开；支持上限由 POC 决定。
- 计数对象是符合范围的签头。断签、碎段、未收费签、赠送等收费规则由门店明确，首版人工处理。

### 5.2 新增与重拍

新拍一把创建新 batch_id；重拍沿用 batch_id，追加 revision。开启重拍后，本把暂不计入可完成合计，其他已确认批次保持有效，页面显示“原 N 根待替换”。

取消重拍恢复上一次已确认版本；确认新版本后仅累计新版本。没有旧确认版本的新批次取消后可移除。

示例：第一把 84、第二把 76，合计 160；重拍第二把时暂计 84，并阻止完成；第二把新确认 75 后合计 159；取消重拍则回到 160。

相同业务请求可以用幂等避免重复写入。同一实物换角度重拍会产生不同图片，不能仅靠图片哈希防重复；必须同时设计物理分区和明确的新增／重拍动作。

### 5.3 计价

- 开单时快照所有可用计价组名称和整数分单价。本单内改组仅选择快照中的组。
- 普通签示例 80 分／根，84 根小计 6720 分。每组数量相加后乘单价，再汇总；禁止浮点金额。
- 未配置价格时允许仅记数量，金额为 null，显示“未计价”；不能显示成 0 元。
- 单价改动不影响已开单和已完成记录。误用旧价时，由店主发起更正单，显式选择新单价格并记录原因。
- 默认不含优惠、菜品、酒水或支付，只显示“签费小计”。

### 5.4 完成与更正

完成前：至少一个有效确认批次，无进行中的替换或未确认批次，所有数量与来源合法。取消或丢弃的尝试不阻塞完成，但必须显式处理对应草稿。

完成事务冻结批次版本、数量、单价、金额与经办人。重复提交返回同一完成结果。

完成后更正：授权人填写原因，创建关联原单的新草稿并复制有效批次；编辑不改变原完成快照。新单完成时原单标为作废并链接新单；取消更正保留原单有效。首版不做任意历史字段编辑。

## 6. 异常交互

| 情况 | 用户看到什么 | 下一步 |
| --- | --- | --- |
| 模糊／出框 | “端面不够清晰／未完整入镜”及示例 | 重拍、分把、人工清点 |
| 无目标／无法定位 | “未得到可复核的签头位置” | 重新拍摄或人工清点；不凭总数直接确认自动结果 |
| 请求超时／排队过长 | 进度停在哪一步，照片与草稿保留 | 重试、稍后继续、转人工 |
| 相机权限拒绝 | 用简短提示解释用途 | 设置权限、选图、人工清点 |
| 网络中断 | “已保留本机草稿，尚未同步” | 恢复联网后继续；不声称云端保存成功 |
| 另一设备更新 | “本单已由另一设备更新” | 保存本机候选修改，刷新比较；不静默覆盖 |
| 编辑中返回 | “已保留草稿” | 返回后继续；不弹出每一步确认 |
| 移除已确认批次 | 显示本把根数与影响，允许撤销 | 明确移除后重算 |
| 证据图片过期 | 数量与签费仍可读，显示图片已过保留期 | 不渲染成图像加载故障 |

## 7. 易用性约束

主动作位于下方易触及区域，触控区域至少 44×44 CSS px（原型）并在真机验证。普通操作不反复弹窗；不可逆的作废、交接和完成更正需要明确说明。

拍摄页只给最关键提示；详细示例按需展开。展示真实阶段，不展示未经校准的置信度。点位颜色与竹签区分，编号默认关闭。

每次确认后提示把本把放入已数区；显示已确认缩略图和累计根数。换桌必须显式开始新单，不能自动清空当前单。

## 8. 追踪与非功能需求

## 9. 次要流程的最小交互

- **首次建店／加入**：已有成员直达工作台；没有门店时展示“创建门店／输入邀请”。提交前展示门店名，邀请过期或次数耗尽明确提示联系店主；登录过期重新登录后回到原草稿。
- **计价组维护**：设置列表中新增／改名／修改单价；停用代替删除已被引用的组。保存提示“从下一单起生效”，当前单不悄悄增加组或换价。
- **交接**：汇总页显示当前经办人；经办人或店主选择一名有效成员，确认后对方接手，原设备转只读并保留候选修改。目标离店或版本冲突时不完成交接。
- **新价更正**：更正表单默认沿用原价，显式切换“采用当前门店价”时先展示差额和缺失组；组不能对应时要求逐把选择，不静默匹配同名组。
- **历史查找**：默认最近记录，按日期、桌号和有效／作废筛选，分页加载；进入明细可见原单与替换单链接。图片过期显示原因，仍保留数量、来源和价格快照。
- **成员停用**：仅店主可操作；提示该成员将不能继续操作本店数据，未完成单需先交接；禁止停用唯一店主。

这些动作复用设置列表、选择器和底部表单，不增加独立运营后台。原型覆盖范围以 02 的明确说明为准。
