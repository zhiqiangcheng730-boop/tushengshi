# 数得快：UI 规范与原型说明

版本 v0.2｜2026-10-16｜[入口](../README.md)｜[打开同一套原型与 UI](../prototype/index.html)

## 1. 设计依据

对象是结账中的店员；页面首先让人知道“当前哪一单、这把多少根、下一步做什么”。视觉气质应清楚、稳定、利落，避免营销横幅和无关动效。

曾比较“纯相机入口”与“任务工作台”。选择轻量工作台：既让常规拍摄一步可达，又保留继续草稿和最近记录，降低被打断后的恢复成本。

采用暖白底、深松绿文字与橙色主动作，呼应竹签、门店招牌与记账单。唯一具有主题辨识度的图形是圆形签束端面；完成明细使用克制的票据分隔。数字醒目服务计数任务，不堆砌装饰性指标。

## 2. 同一 HTML 的结构

桌面为设计评审工作台：左侧页面导航，中间手机画布，右侧当前页面目标与情境控制；窄屏将情境控制放到手机画布下方。手机宽度基线 390px，窄屏自适应。

“视觉 UI／线框原型”只切换 CSS 样式，页面结构、文案、事件、状态和金额计算共用。不会维护两套互相漂移的原型。

手机内仅展示店员需要的业务信息；模型、候选区域、测试情境和需求编号在外部评审区说明。

## 3. 视觉 token

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 画布 | #F5F7F4 | 手机工作区背景 |
| 表面 | #FFFFFF | 内容卡片与底部操作 |
| 主文字／深色区域 | #183D32 | 标题、数值、品牌识别 |
| 主动作 | #C84B1D | 拍摄、确认、完成 |
| 辅助文字 | #68756D | 时间、单位与解释 |
| 成功浅底 | #E8F1E9 | 已确认状态 |
| 错误 | #B3342C | 错误与危险动作 |
| 分隔 | #E1E7E1 | 边界、票据分隔 |
| 点位 | #1676D2 + 白描边 | 与端面区分；人工补点用不同形状／说明 |

主动作底色与白字的计算对比度约 4.69:1；辅助文字与白底约 4.82:1。按钮、切换和输入的焦点可见，状态同时使用文字表达。

字体：中文采用本机 PingFang SC／Microsoft YaHei，正文与标题使用同一字族；关键数字使用系统数字字体及 tabular-nums。标题 22px、正文 16px、辅助 13px、核心根数 56px，主要字重 400／600。

间距采用 4／8px 倍数；手机页边距 20px，内容卡片间距 16px。底部主按钮 52px 高；44px 最小触控区域，不把可见小图标本身作为唯一热区。

## 4. 主要页面布局

| 页面 | 信息层级 | 操作层级 |
| --- | --- | --- |
| 工作台 | 门店 → 当前任务／开始 → 最近记录 | 开始数签主按钮；草稿直接继续 |
| 拍摄 | 当前单与组别 → 取景 → 两条提示 | 拍照为主，相册为辅 |
| 识别中 | 当前阶段 → 仍可继续的说明 | 取消／人工兜底，不反复点击提交 |
| 复核 | 根数 → 照片 → 编辑工具 → 单价 | 浏览为默认；补／删为显式模式；确认在底部 |
| 汇总 | 已确认总数 → 各把 → 签费小计 | 继续下一把／完成；重拍位于对应批次 |
| 完成 | 完成状态 → 签费 → 按组明细 | 开始下一桌；证据与更正在次级位置 |
| 记录 | 日期／桌号／状态 → 根数／签费 | 点开详情，区分作废 |
| 设置 | 价格 → 成员 → 数据使用 | 店主可保存，店员只读 |

## 5. HTML 可体验的行为

- 页面导航；同一结构的视觉／线框切换。
- 开单、选填桌号、选择组别、示例拍摄与示例相册。
- 模拟等待、模糊拒识和超时情境，失败转人工。
- 点位显示、缩放／拖动、补点、删点、撤销、编号开关。
- 人工录入、确认、多把累计、重拍替换、取消替换恢复原值。
- 完成检查、按组计价、历史明细、关联更正、放弃更正保留原单。
- 修改门店价格只影响新单；角色切换展示只读差异。
- 本地草稿恢复和重置演示。

演示图为程序绘制的竹签端面示意。首把自动点位为 84，下一把为 76，图中额外可见端面用于演示补点；这些数字无真实照片或模型依据。

## 6. 演示边界

HTML 不调用真实相机／相册授权、不做图片上传、不调用模型、不生成真正的邀请码或微信会话。示例相册只选用内置示意图。等待时间为演示动画，不是推理延迟测试。

本地浏览器存储用于演示恢复，不代表微信小程序的存储可靠性或服务端持久化。并发编辑、门店鉴权、数据库事务、备份和真实弱网都需要按 06 单独验证。

HTML 的放大与拖动验证交互意图；小程序必须用真机验证手势、图片旋转、设备像素比与坐标反变换。画布上的模拟像素不能代替真机适配结论。

原型集中演示日常清点与纠错；实际建店、经办人交接、计价组增删／改名、成员停用、选择新价更正、记录筛选等管理动作已在产品与接口中定义，本 HTML 未完整展开。实施时使用现有列表／表单／底部弹层模式补齐，按对应任务与测试验收，不另建设复杂管理后台。

v0.3补充的最小平台运营后台、服务期限／用量和数据导出／退出只完成文档设计，见[09](09-后台管理方案.md)与[10](10-收费与服务权益方案.md)。D07已确认面向多店收费，按K系列计划在同一HTML追加对应交互并实现业务；不将门店基础设置与平台管理混为一个权限体系。

## 7. 评审方法

先完整体验两把累计，再试重拍第二把、取消替换、人工改数、改组、完成、重置后恢复草稿。切换为线框后复查动作名称和信息层级，确保视觉不会掩盖流程问题。

请重点判断：一手握签一手拿手机时是否顺手；是否知道当前哪把待确认；是否能轻松撤销；完成前是否能解释每组签费。具体检查记录见 [07](07-交付校验记录.md)。
