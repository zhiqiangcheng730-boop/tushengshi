# 数得快：数据存储与生命周期方案

补充稿 v0.3｜2026-10-16｜待资源／期限冻结｜[入口](../README.md)

## 1. 已有基础与本次补齐

03已有PostgreSQL、私有图片、图片30天／清点记录90天建议、每日备份与恢复目标；本稿补齐数据分类、容量、孤立文件、清理、导出、注销和恢复后的删除重放。

期限是待确认的产品配置，不是法规结论；原图、统计、账据、训练材料不能统一“永久保存”，也不能全部套用同一个TTL。

## 2. 数据放在哪里

| 数据 | 位置／访问 | 默认建议 |
| --- | --- | --- |
| 门店、成员、清点单、批次／修订、点位、价格快照 | PostgreSQL，服务端按门店和身份限制 | 清点记录90天，门店／成员保持有效服务必需数据 |
| 上传原图、转正canonical图、缩略图 | 私有对象存储；DB仅存storage_key、哈希、尺寸、状态、期限 | 同一图片资产组30天；辅助版本不得偷偷长期保留 |
| 模型原始输出、诊断材料 | 受限对象或受限DB字段 | 常规建议7天；服务单需要延长时有范围、授权和到期，不混入普通日志 |
| 任务状态、耗时、使用量 | PostgreSQL，按请求和门店关联 | 详细任务随业务90天；经营用汇总不保留图片和个人标识 |
| 普通服务日志 | 统一日志服务，不含图片／token／下载凭证 | 建议14天；异常留存另走服务单 |
| 操作审计 | 追加记录，独立查询权限 | 初始建议180天；白名单保留动作／ID／必要变更摘要，不复制完整订单、图片、点位或敏感原文绕过业务期限 |
| 服务订单／付款／退款／权益 | 与清点账分开的业务表 | 按收费前冻结的财务保留规则，不使用清点90天自动删除 |
| 独立评测／训练样本 | 与业务图片分开的私有位置，manifest追踪授权来源 | 单独声明用途、保留和撤回规则；默认不进入训练 |
| 本机草稿和图片缓存 | 微信受控本地文件／存储，不当作云端备份 | 云端同步成功或显式放弃后清理；在本机设置过期策略 |
| 数据库备份与删除清单 | 与生产访问隔离的备份位置 | 建议滚动14天，访问留痕，恢复前执行删除重放 |

服务端根据业务时钟写 expires_at，界面展示具体到期规则。图片期限以上传为起点，完成清点不能重置旧图的保存时钟；清点记录建议以完成为起点，未完成草稿另外建议7天无活动后到期，实施前在门店确认。

## 3. 目录与最小部署

试点继续采用一套PostgreSQL＋一个私有对象存储桶，使用环境／门店／图片ID前缀，例如 `prod/<store_id>/<media_id>/canonical.jpg`；对象名不含真实门店名称、桌号、联系人。前缀只是组织方式，真正隔离由API鉴权和存储访问权限执行。

开发、试点和正式环境不混桶或混数据库。POC可以本地文件；门店多人使用、跨机器worker和正式服务时迁到私有对象存储，ID与业务契约保持不变。先单地域部署，不搭跨地域双活；地域在性能、资源和适用要求核验后冻结。

原始图片不进普通源码仓库，不将图片二进制塞进订单JSON。开启传输及静态加密、最小服务账号权限，下载凭证短期有效；平台诊断按09单独授权。文件上传后实测格式、大小、解码尺寸并去除非必要EXIF。

## 4. 容量怎么算

稳态图片容量GB ≈ 门店数N × 每店每日清点桌数D × 每桌把数B × 含重拍的图片倍数R × 每组文件总大小MB × 保留天数H ÷ 1000。

总大小包括原图＋canonical＋缩略图，不能只算用户上传图；原图哈希相同也不能擅自跨店去重或共享权限。

纯假设示例：10店、每店80桌／天、每桌3把、重拍倍数1.2、每组文件2MB、保留30天，则每天约5.76GB，稳态约172.8GB，约86400组图片。90天清点记录约72000单。图片大小与重拍比例必须用T19／试点数据替换，这不是压缩策略或容量承诺。

月成本分别统计GPU、API／数据库、存储容量、上传／读取／删除请求、外网下载、备份、监控与人工支持。对象存储费用有容量、请求与流量等维度，不能只算GB价格。[腾讯云COS计费说明](https://cloud.tencent.com/document/product/436/16871)

图片仅保留30天时建议先标准存储，暂不建设冷热分层；低频／归档可能有最短存储时长和提前删除成本，选型前按当前供应商规则核对。[COS存储费用说明](https://cloud.tencent.com/document/product/436/53482)

数据库容量用实际行大小、点位数量、索引和增长率测算，不按“72000单很少”直接选硬盘。设置预算与磁盘阈值，容量不足先暂停新上传／自动任务，确保已有记录可查询和人工收尾。

## 5. 数据生命周期与失败处理

1. **上传**：生成media_id，状态UPLOADING；写入对象成功并校验后转READY，才可创建模型任务。
2. **关联**：订单修订或识别任务引用图片；事务失败或用户放弃产生的无引用对象由定时任务识别。初始建议24小时无引用后清理，不能误删正在上传／重试或已有引用对象。
3. **服务**：按权限短期读取；点位始终绑定canonical尺寸和变换。人工无照片的数据不得伪造图片引用。
4. **到期**：业务时间到期立即禁止新签发访问凭证，界面显示“已过保留期”；已签凭证的最大剩余有效期需要计入访问失效说明。
5. **清理**：状态转EXPIRED／DELETING，删除原图、canonical、缩略图、诊断副本及需处理的历史版本；成功确认后标DELETED，保留必要墓碑元数据，不伪报物理删除完成。
6. **失败重试**：对象不存在视为幂等成功；权限／存储故障记录错误并重试，超过内部目标告警，不能静默永久积累。

对象存储生命周期规则可作兜底，但实际执行是异步的，不能将配置规则当成精确业务时刻的访问撤销；业务失效由API先控制。[官方生命周期配置](https://cloud.tencent.com/document/product/436/17031)

若开启对象版本控制，只删除当前对象或加删除标记不等于旧版本已清理。首版只在确有恢复需求时启用，启用后必须覆盖旧版本、删除标记和未完成分片的生命周期，成本也计入。业务记录过期清理采用显式引用顺序与审计摘要，不能误级联删除尚需保留的服务订单或同店有效图片。

## 6. 导出、到期与门店退出

店主可在数据保留期限内导出本店清点单、各把数量／来源／价格快照、更正关系；默认CSV／JSON，图片另选，已过期图片标记状态。导出不包含微信凭据、平台诊断秘密或其他门店数据。

数据请求包括request_id、store_id、发起人、范围、截止时间、状态、结果引用。大导出使用后台任务、限并发和短期下载，完成后校验行数与范围；导出文件建议24小时清理。重复请求不会生成无限份永久副本。

服务到期与数据到期分开：未续费不立即删历史，保留期限也不会因停服务停止计时。到期提醒同时显示最近图片的过期规则和导出入口。续费不承诺恢复已经删除的文件。

门店注销流程：验证店主与门店 → 明示数据范围、仍需保留的凭据及备份窗口 → 可先导出 → 停止新任务／写入 → 清理在线数据与对象 → 记录删除进度与完成范围。财务／必要审计按独立期限处理，不能以后台“已关闭门店”冒充全部数据已删除。

## 7. 备份与恢复

受控试点延用每日数据库备份，RPO≤24h、RTO≤4h是待演练目标。付费前需明确门店可接受的数据丢失窗口；若不可接受24h，升级托管PITR／WAL备份并验证其成本和恢复时间，不能仍用每日备份承诺更小RPO。[PostgreSQL备份与恢复](https://www.postgresql.org/docs/current/backup.html)

数据库备份不能替代图片备份。是否启用对象版本／独立副本，按承诺的数据丢失窗口决定，明确额外容量、清理与关联恢复测试。导出只是用户副本，不是平台灾备。

G6前必须选定并实际演练数据库与图片各自的恢复方案，记录覆盖范围、恢复点、恢复时间和无法恢复的边界；不能将“是否备份待定”留到已收费之后。若依赖供应商冗余，也需说明其不能替代误删恢复。

删除清单单独保存删除请求ID、不可反推内容的资源标识、范围和时间，不保存被删原文；与生产备份分开维护。备份保留期内的数据不能承诺立即物理消失，但不能继续用于日常查询。

恢复必须在隔离环境进行：选备份 → 恢复DB／图片关联 → **重放备份时间之后的删除、撤权及成员停用记录** → 核验过期资源与门店隔离 → 核对订单和对象 → 恢复访问。相关安全动作写入数据库并持久化到独立重放清单；清单持久化失败时请求保持未完成，不能提前宣称删除／撤权已完成。避免恢复旧备份让已删照片或已离店账号重新可用。

重放按资源版本与动作顺序执行，合法重新授权也有对应新版本，不能把历史停用永久盖过后来的有效决定。清单保留至少覆盖最老可恢复备份及恢复演练窗口，禁止先清理清单再保留对应旧备份；备份到期后按最小必要范围清理。

## 8. 数据改进与验收

训练选择默认关闭。服务照片进入改进流程需有独立用途、来源记录与复核；人工修改不是自动训练标签。撤回后停止新增采集，并按既定规则处理尚未使用的样本；已发布模型的处理策略需事先说明，不承诺删除一张图就能精确撤销模型影响。

上线前验证：跨店访问、图片过期、孤立文件、删除失败重试、旧版本对象、导出越权／到期、注销与备份恢复重放、财务记录不误删。相同任务重复执行结果一致；有物理清理失败则显示未完成并告警。任务与测试映射见05的K系列。
