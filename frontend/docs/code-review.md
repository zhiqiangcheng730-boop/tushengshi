# 前端代码评审清单

## 1. 正确性与范围

- 变更是否只覆盖需求，是否保留既有文档、原型和未相关代码？
- 正常、边界、非法、重复、迟到和取消路径是否有证据？
- 页面显示状态是否来自明确 owner，服务端事实是否被客户端错误推断？

## 2. 架构与契约

- 页面/Presentation 是否绕过 Application 或直接调用 `wx.request`、存储、文件能力？
- 是否出现反向依赖、循环依赖、深层跨模块导入或第二套协议类型？
- OpenAPI 未冻结时是否避免伪造契约；冻结后生成代码是否可重复且禁止手改？

## 3. 小程序生命周期与体验

- 请求、计时器、监听和订阅是否在隐藏/卸载时释放，迟到结果是否会覆盖新状态？
- `setData` 是否为最小差量，触摸高频路径是否避免大对象与同步重计算？
- WXML/WXSS 是否遵循语义 Token、触摸目标、安全区、大字体与非颜色状态表达？

## 4. 安全、隐私与供应链

- 页面参数、微信回调、缓存和 API 响应是否在边界校验？
- 是否可能记录 token、OpenID、私有图片地址、原图内容或 AppSecret？
- 新依赖是否必要、精确锁定、许可可接受、无高危生产漏洞且包体影响可解释？

## 5. 验证与交付

- 新生产行为是否有先失败后通过的自动化测试？
- `pnpm verify` 是否无 warning、skip、flaky 或未解释失败？
- 自动化无法覆盖的微信开发者工具、真机、授权、相机和弱网证据是否明确列出，而非暗示已通过？
- 回滚是否只影响本次新增/修改内容，是否会误删用户数据或已有文档？
