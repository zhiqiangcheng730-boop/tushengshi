## 查看 HTML

原型为单文件 HTML，无构建步骤、无外部字体或脚本依赖，可直接用浏览器打开。也可在本目录运行：

~~~bash
python3 -m http.server 8791 --bind 127.0.0.1
~~~

随后访问 [本地预览](http://127.0.0.1:8791/prototype/index.html)。仅启动上述命令后该链接可用。

这是设计原型：使用明确标注的示意签束和模拟识别结果；没有接入相机、微信身份、模型、支付或真实云端存储。演示草稿和设置仅保存在当前浏览器，可通过“重置演示”清除。

## 当前基线

- 已确认：前期 Qwen3-VL-2B（MLX 4bit）；上线前 VLX-Seek 10B 验证；精准要求 98%；候选区域至少 200 个为后续优化目标。
- 未确认：98% 的统计口径、实际支持的单把根数范围、硬件和预算。文档提供建议定义，不将建议写成用户已确认结论。
- 当前缺少稳定的真实门店样本。模型效果、费用和推理速度均未实测。
- 本次产出是产品、UI、研发设计与计划；实际业务系统尚未开发。
- 以 1 名熟练全栈开发配合 AI 为估算前提：基线 39 人日，风险预算 8 人日，结合试点观察预计约 10～11 周；外部样本和硬件等待另计。
- 商业方向已确认：面向多家独立门店收费，按门店隔离数据、价格、成员和软件服务权益。每店订阅仍是设计建议；199 元／月及额度只是验证假设，不能直接对外报价。
- 最小商业运营能力纳入正式分阶段规划，另估 19 人日＋4 人日缓冲，约增加 4～5 周；与试点合计约 14～16 周。在线支付另估 9 人日＋3 人日缓冲，接入资格与外部等待另计。
- 现有 HTML 展示店员清点与基础门店设置；平台后台、订阅和数据请求本次只完成文档设计，未制作对应交互页面。

## 前端工程底座

2026-10-20 起，`apps/miniapp/` 提供原生微信小程序 TypeScript 工程底座；原有 `docs/` 与 `prototype/` 保持为产品、交互和验收事实源。当前只包含应用壳和首页，不表示拍摄、识别、微信身份、业务 API 或商业功能已实现。

工程入口：

- [前端架构](ARCHITECTURE.md)
- [工程代码规范](engineering-standards.md)
- [协作与交付规范](CONTRIBUTING.md)
- [安装、构建与微信开发者工具导入](docs/architecture-bootstrap.md)

在本目录执行：

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm build
pnpm verify
```

构建输出位于 `apps/miniapp/dist/` 且不提交。自动化验证不能替代微信开发者工具和真机测试；对应边界与设备矩阵仍以 [06｜测试与验收计划](docs/06-测试与验收计划.md) 为准。
