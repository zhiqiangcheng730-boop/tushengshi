# AGENTS.md

## 1. 适用范围与事实源

本文件适用于 `frontend/` 及其全部子目录，是该前端子树唯一的 Agent 行为规范。不得新增 `CLAUDE.md`、`.cursor/rules`、嵌套 `AGENTS.md` 或复制本文件的工具专属指令。

| 主题                  | 唯一来源                                |
| --------------------- | --------------------------------------- |
| 项目实例与工具链事实  | `architecture-profile.yaml` 及其 Schema |
| 前端架构边界          | `ARCHITECTURE.md`                       |
| 代码和工具规则        | `engineering-standards.md` 与可执行配置 |
| Git、Commit、PR、合并 | `CONTRIBUTING.md`                       |
| 产品行为              | `docs/01-产品需求与交互设计.md`         |
| UI 与交互设计         | `docs/02-UI规范与原型说明.md`           |
| 验收口径              | `docs/06-测试与验收计划.md`             |

发现规范、配置和实现冲突时，必须在同一变更中恢复一致，不能选择较宽松的一份继续工作。

## 2. 开始任务前

1. 阅读本文件、`ARCHITECTURE.md`、`engineering-standards.md`、`CONTRIBUTING.md` 和 `architecture-profile.yaml`。
2. 检查工作区，区分用户已有修改与本次修改；不得覆盖、清理或格式化无关内容。
3. 把需求转化为可运行的完成条件，多步骤任务写出验证方式。
4. 先搜索现有实现、契约、常量和配置，不因未搜索就建立第二套能力。
5. 明确假设。会改变产品语义、架构、安全或外部状态的假设必须由 owner 确认。

## 3. 实施原则

- 只实现需求所需的最小完整方案，不建立无真实调用者的抽象、页面、模块或依赖。
- 现有产品文档和原型是受保护输入；除非任务明确要求，不得移动、删除或批量重排。
- 原生微信小程序是唯一用户端运行目标，不引入跨端框架或浏览器 SPA 技术体系。
- 外部 API、微信回调、存储、页面参数、文件与配置均为不可信边界，必须验证后进入业务逻辑。
- 不通过放宽 TypeScript、ESLint、测试、覆盖率、架构或安全规则来绕过失败。
- 依赖版本必须精确锁定；新增依赖前证明真实使用者、许可证、供应链和包体影响。
- 不执行破坏性 Git 操作，不改写共享历史，不擅自提交、推送、发布或修改外部系统。

## 4. 架构边界

- 页面和展示层不直接调用 `wx.request`、持久化或后台契约；远程 I/O 只能经 `shared/http` 与模块基础设施适配器。
- Application 层不依赖 Page/Component 实例、Transport DTO 或 Infrastructure 实现。
- `shared/` 不依赖业务模块、页面或 App 组合根。
- OpenAPI 契约冻结前不得伪造生成客户端；生成代码只能位于 `generated/` 且禁止手改。
- `dist/` 是可重建输出，不得提交。

## 5. 验证与交付

生产代码修改必须有自动化测试证据。先运行受影响测试，再运行 `pnpm verify`；真机、相机、微信身份或开发者工具无法在本地自动化时，必须明确列为未执行，不能宣称已通过。

完成前确认实现、测试、配置、架构文档和现有产品文档一致，无 warning、skip、flaky 或未解释失败。最终报告必须以以下两行结束：

`风险: <残余风险、未完成验证或已知限制；无则写无>`

`后续: <待办、下一步和 owner；无则写无>`
